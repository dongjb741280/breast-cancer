## Question

评测协议定稿：系统输出（[03] 的 schema）如何对齐「诊疗金标准」（[01] 的形态）。注意金标准是**自由文本**——REAL 是「统一六项评测金标准」（人群判断/治疗线/治疗建议/证据依据/风险提示/资料补充）散文、BC 是 MDT 结论 + 阶段小结「考察点」，均无机器可读等级码。

故「什么算对」需重新定义：端到端是否用 LLM-as-judge 按六项/考察点打分？检索层单独看精确/召回？等级如何从文本金标准里提取来比对？指标怎么定。

## Answer

**评测协议 = 两层。**

**Layer 1 — 端到端（LLM-as-judge 为主 + 少量人工抽查校准）**
- 输入：系统输出 + 病例 + 金标准文本。
- rubric：REAL 六项（人群判断 / 当前治疗线 / 治疗建议 / 证据依据 / 风险提示 / 资料不足补充）、BC 考察点。
- 判分：逐项 pass/fail → 每例正确率 = 过项数 / 总项数（取均值，非「全过才算对」）。
- 校准：少量人工抽查，防 judge 漂移。

**Layer 2 — 检索层（确定性信号）**
- ground truth = 金标准文本里出现的方案名（模糊匹配，因无干净 relevant-set）。
- 指标 = `recall@3` / `precision@3`。

**口径裁定**
- 不做 Ⅰ/Ⅱ/Ⅲ 的 exact-match（金标准无等级码）；「治疗线 / 人群判断」一致性作为 LLM-as-judge 六项里的独立一项。
- 评测集 = 全量 27（7 REAL + 20 BC），REAL / BC 分档报告；BC 内部再按 001~010 / 011~020 两代看。
